# WCAG 2.2 AA across the packages and the blog

Date: 2026-09-29. Owner: Curt. Status: implemented on dev 2026-10-03, released as v0.11.1 at tag time;
approved 2026-09-29 (v0.11.1, nudge
approved in principle); sections 2 and 3 revised the same day from
prototype measurements, see "Prototype results".

Source: the 2026-09-29 WCAG 2.2 audit of half-built-robots.com, run from
the blog session against production (`main`). The blog's accessibility
statement currently says "partially conformant with WCAG 2.1 Level AA",
and both repos' axe suites run the 2.1 tag set only. This spec moves the
target to WCAG 2.2 Level AA, ui repo first.

## Goal

Both axe suites check WCAG 2.2 A and AA. Every component the packages
ship passes 2.5.8 Target Size (Minimum) in both themes, at desktop and
phone widths. The blog adopts the fixed release with no blog-side CSS
change and then states 2.2 AA in its accessibility statement.

## Decisions

Settled with Curt on 2026-09-29.

1. The ui repo goes first: the stricter gate and the fixes land here
   and ship in a release, and the blog adopts by pin bump. The blog's
   suite becomes the second check, not the first.
2. Both suites add the 2.2 tags (`wcag22a`, `wcag22aa`) to the existing
   2.1 set. Best-practice rules stay out, as today, so a failure still
   always maps to a success criterion.
3. The criteria axe cannot automate (2.4.11, 2.5.7, 3.2.6, 3.3.7, 3.3.8)
   were checked by hand in the audit and pass. They are recorded here,
   not turned into new tests.

## Audit findings

Method: headless Chrome at 1280px and 390px in both themes, the blog's
17 audited templates, axe with the 2.2 tags, a keyboard Tab walk on
seven pages that measures sticky or fixed overlap of the focused
element, and the lightbox and fluid demo audited in their open state.

| Criterion | Result |
|---|---|
| 2.5.8 Target Size (AA) | **Fails** in two package components (below) |
| 2.4.11 Focus Not Obscured (AA) | Passes. The only fixed elements are the scroll-top button and the link tip; worst overlap was about 4% of one link, and the criterion fails only on full concealment. Phone layouts have no fixed elements. |
| 2.5.7 Dragging Movements (AA) | Passes. Lightbox pan is drag-only, but double-click or double-tap zooms to 100% at the chosen point and again returns to fit, so any region is viewable without dragging; prev/next buttons cover swipe. The path player's timeline seeks on a single press. Popout swipe-to-dismiss has the close button. |
| 3.2.6 Consistent Help (A) | Passes. The footer's Contact link keeps its place on every page. |
| 3.3.7 Redundant Entry (A) | Not applicable. The only form is the one-field subscribe. |
| 3.3.8 Accessible Authentication (AA) | Not applicable. No logins. |

The 2.5.8 failures, all 16px tall:

1. **PostCard category links** (`.entry-cat .post-categories a`), on every
   listing page, at both widths. The row is one comma-joined line with
   `line-height: 1`, ellipsized (an owner-approved divergence, do not
   restore the wrapping list), and it sits close to the thumbnail link
   above and the title link below.
2. **Footer sitemap links on phones** (`.footer-sitemap-group li a` under
   `--bp-phone`) with a group open. The links are 16px tall at a 24px
   pitch (`li { margin: 4px 0 }`), which misses axe's spacing exception.
   Desktop passes (19px at a 27px pitch).

The blog's own post footer ("Posted in", "Tagged") passes, so the blog
needs no CSS of its own.

### Prototype results

Measured against production with CSS injected into a local headless
browser (nothing deployed), transitions frozen, axe `wcag22aa`:

- Card, hit area only (row `padding-block: 4px; margin-block: -4px`,
  links `padding-block: 4px`): still fails. The grown boxes meet the
  title link below.
- Card, plus 2px of room below the row only (`margin-block: -4px -2px`):
  passes at 1280px and 390px. Every 1px variant, and 2px above instead
  of below, still fails. The title and everything under it move down
  2px.
- Footer, the originally specced `inline-block` plus 4px padding:
  passes, but each link box becomes 27.2px and the pitch grows from
  23.3px to 27.2px, which changes the rhythm.
- Footer, `inline-block` with `line-height: 24px` and `li` margin 0:
  passes. Boxes are 24px at a 24px pitch (today 16px boxes at 23.3px),
  so the text moves by under a pixel per line. The open footer loses
  the first and last `li` margins, about 15px shorter overall on the
  sampled page.

An earlier run that seemed to show padding not applying was measuring
mid-transition (the links carry `transition: var(--transition)`); any
geometry check must freeze transitions first, as the suites already do.

## 1. The ui suite checks 2.2 (tests first)

`site/test/browser.test.ts`:

- `RUN.runOnly.values` gains `wcag22a` and `wcag22aa`. The comment and
  the test names change from "WCAG 2.1 AA" to "WCAG 2.2 AA".
- A new test audits the demo page at phone width (390px) in both themes
  with every `details.footer-sitemap-collapsible` opened first, since
  the footer failure only shows with the groups open. It reuses the
  existing ecosystem fixture so the island-driven list is deterministic.
- Run it before any fix and confirm it fails on exactly the two
  findings above. Any other component it flags joins this spec's scope
  (a package component gets fixed in the package; demo-only markup gets
  fixed in `site/`), and the plan records each one.

## 2. PostCard category links

`packages/astro/src/components/PostCard.astro`.

- Constraint: the card layout stays as approved. The category text, the
  title, and the thumbnail keep their positions, the row stays one
  ellipsized line, and the existing smoke test that pins the row's
  containment keeps passing.
- Approach (revised from the prototype): grow each link's hit area to
  24px with the row's existing padding-plus-negative-margin trick
  (row `padding-block: 4px`, links `padding-block: 4px`), and give back
  2px less margin below the row (`margin-block: -4px -2px`), so the
  title and everything below it sit 2px lower. Hit area alone does not
  pass; this is the approved nudge.
- The hover and focus ring (inset outline) grows with the link box.
  That is visible and gets reviewed on screenshots.
- The 2px shift is approved in principle. Implementation still shows
  before and after screenshots of the demo card grid at both widths
  before committing it.

## 3. Footer sitemap links on phones

`packages/astro/src/components/Footer.astro`, inside `@media (--bp-phone)`.

- Constraint: the text rhythm stays as close as possible to today's
  (23.3px pitch on phones). Desktop is untouched.
- Approach (revised from the prototype): the link becomes
  `inline-block` with `line-height: 24px`, and the `li` margin drops to
  0 on phones. Each link is 24px tall at a 24px pitch. The first and
  last `li` margins go with it, so each open group is a few pixels
  shorter.
- Verify with screenshots of the open footer at 390px, before and after.
  Tapping between items should read the same.

  not over it.
