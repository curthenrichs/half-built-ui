# half-built-ui 0.12.0 (StatLedger, Meter, Subscribe messages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship @half-built 0.12.0 with two new Astro components (StatLedger, Meter), a `messages` prop on Subscribe, and the html-validate allowlist entries Meter needs, demoed on the ui site and released by tag.

**Architecture:** Both components are style-scoped `.astro` files with no JS, like `Widget.astro`. Subscribe's status lines ride the form as `data-messages` JSON and `mountSubscribe` merges them per form. Coverage follows the repo's split: jsdom tests in `packages/astro/test/` for scripts, the site's browser suite (`site/test/browser.test.ts`, axe in both themes) for rendered components.

**Tech Stack:** Astro 5, TypeScript, Vitest (jsdom + browser suite via puppeteer-core), axe-core, html-validate, npm workspaces.

**Spec:** `docs/superpowers/specs/2026-10-06-beadz-components-design.md` (consumer context: the private BEADZ facelift spec it points to).

## Global Constraints

- No new theming tokens. Colors come from semantic tokens only (`--ink`, `--ink-muted`, `--rule`, `--band`, `--accent-1-ink`, `--stroke`).

## Review Focus

1. A Subscribe `data-messages` value that is malformed JSON, an array, or holds non-string values: expect the defaults, never a thrown error or `undefined` printed in the status line.
2. A consumer that passes both mount-option `messages` and the component prop: the form's own value wins, per key.
3. `Meter` with `value` above `max`, below 0, or `max` of 0: expect a clamped, valid `aria-valuenow` and a fill of 0 to 100%, never NaN.
4. `StatLedger` at phone width with long values: cells stack and values wrap inside the box rather than overflowing the page.
5. Both components in the dark theme: axe clean (the existing "/" dark-theme axe test covers the demo once it renders there).

Each line above is pinned by a test in the task that owns the code (Tasks 1 to 3).

In `packages/astro/src/scripts/subscribe.ts`, after `MSG`:

```ts
const MESSAGE_KEYS = ["invalid", "pending", "sent", "failed"] as const;
type MessageKey = (typeof MESSAGE_KEYS)[number];

/* The component's messages prop rides the form as JSON (data-messages),
   because the component mounts itself and a consumer cannot reach that
   call. Only the four string lines are read: failedAt stays the
   package's, and anything malformed falls back to the defaults rather
   than printing a broken status line. */
export function formMessages(
  form: HTMLFormElement,
): Partial<Record<MessageKey, string>> {
  const raw = form.dataset.messages;
  if (!raw) return {};
  let parsed: unknown;

  try {
    parsed = JSON.parse(raw);
  } catch {
    return {};
  }

  if (typeof parsed !== "object" || parsed === null || Array.isArray(parsed)) {
    return {};
  }

  const out: Partial<Record<MessageKey, string>> = {};

  for (const key of MESSAGE_KEYS) {
    const value = (parsed as Record<string, unknown>)[key];
    if (typeof value === "string" && value !== "") out[key] = value;
  }

  return out;
}
```

`packages/astro/src/components/Meter.astro`:

```astro
---
/* A segmented progress bar. role="meter" carries the value for
   assistive tech; the fill and the segment ticks are drawn from two
   inline custom properties, so the component ships no script. value is
   clamped to 0..max, and a max of 0 reads as empty rather than NaN. */
interface Props {
  value: number;
  max: number;
  label: string;
  segments?: number;
  valueText?: string;
  class?: string;
}

const {
  value,
  max,
  label,
  segments = 10,
  valueText,
  class: className,
} = Astro.props;

const top = Math.max(max, 0);
const now = Math.min(Math.max(value, 0), top);
const share = top > 0 ? (now / top) * 100 : 0;
---

<div
  class:list={["meter", className]}
  role="meter"
  aria-label={label}
  aria-valuemin="0"
  aria-valuemax={top}
  aria-valuenow={now}
  aria-valuetext={valueText ?? `${String(now)} of ${String(top)}`}
  style={`--meter-fill: ${String(share)}%; --meter-segments: ${String(segments)};`}
>
  <div class="meter-fill"></div>
</div>

<style>
  .meter {
    position: relative;
    height: 18px;
    background: var(--band);
    border: var(--stroke) solid var(--rule);
  }

  .meter-fill {
    width: var(--meter-fill, 0%);
    height: 100%;
    background: var(--accent-1-ink);
  }

  .meter::after {
    position: absolute;
    inset: 0;
    background: repeating-linear-gradient(
      to right,
      transparent 0 calc(100% / var(--meter-segments, 10) - 2px),
      var(--rule) calc(100% / var(--meter-segments, 10) - 2px)
        calc(100% / var(--meter-segments, 10))
    );
    content: "";
    pointer-events: none;
  }
</style>
```
