# WCAG 2.2 AA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both axe suites (half-built-ui demo site, then the blog) check WCAG 2.2 A and AA, the two package components that fail 2.5.8 Target Size are fixed and shipped as `v0.11.1`, and the blog adopts it and states 2.2 AA.

**Architecture:** ui repo first. Bump to 0.11.1, add the 2.2 axe tags and fix `PostCard.astro` (category links: 24px hit area plus a 2px nudge below the row), then add a phone-width footer audit and fix `Footer.astro` (phone link boxes at `line-height: 24px`). Release by merge, tag, push. The blog then bumps its pins, adds the same tags (and opens the phone footer before auditing), and updates its accessibility statement. No blog CSS changes.

**Tech Stack:** Astro 5 components with scoped CSS, vitest, puppeteer-core, `@axe-core/puppeteer` (ui) and injected `axe.min.js` (blog), npm workspaces, GitHub Actions `release.yml` with npm trusted publishing.

**Spec:** `docs/superpowers/specs/2026-09-29-wcag-2-2-design.md` (read it first, especially "Prototype results").

## Global Constraints

- Version: `0.11.1` for `@half-built/css`, `@half-built/astro`, `@half-built/tooling`, the three `@half-built` pins in `site/package.json`, and later the blog's three pins.
- axe tag set in both suites: `["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22a", "wcag22aa"]`. No best-practice rules.
- Card fix values (from the spec): row `padding-block: 4px; margin-block: -4px -2px`, links `padding-block: 4px`. The row stays one ellipsized line.
- Footer fix values (from the spec), phones only (`@media (--bp-phone)`): `li { margin: 0; }`, links `display: inline-block; line-height: 24px;`. Desktop untouched.
- Any geometry check freezes transitions first (the links carry `transition: var(--transition)`, which animates padding).
- No em dashes anywhere. Formatting is tooling's job: run `npm run lint:fix`, never hand-format.
- Commit on `dev` only, by path. Never push `main`. Do not push anything unless Curt asks.
- Scratch files (screenshot script, images) live outside both repos, in the session scratchpad, never under the repo tree (a scratch build in the blog once flooded the dev-server watcher).
- Before editing the blog clone: `git status`, and check with any peer session working there (ListAgents, then message it). The blog's 0.11.0 pin bump by a peer must be committed before Task 5 starts.
- After any pin bump or `npm install` in the blog, a running `astro dev` must be restarted (the Vite dependency cache goes stale and dynamic imports 504).

## Review Focus

1. Keyboard focus ring on a card category link after the padding change: the inset ring must still show on all four sides inside the row's clip box. Pinned by the containment test in Task 2 (ui) and the blog's existing `browser-smoke.test.ts` containment test in Task 5.
2. Desktop footer must not change. Pinned by the desktop-margin assertion in Task 3.
3. A long category list (overflowing the card width) must still ellipsize on one line, not wrap. Pinned by the single-line assertion in Task 2.
4. The hover outline on a category link grows from 16px to 24px tall. Not testable by assertion; covered by the Task 2 screenshots, which include a hovered link.
5. Dark theme: the fixes must not introduce a contrast or target failure in dark. Covered because every axe test here runs both themes.

- [ ] **Step 2: Add the card geometry test**

Directly after the dark-theme axe test (the one ending `expect(violations, report("dark", violations)).toEqual([]);`), add:

```ts
  /* The category row's 24px targets (2.5.8) must not cost the ring or
     the one-line ellipsis: each link's border box stays inside the
     row's clip box, so the inset focus ring keeps all four sides, and
     the row stays a single line however many categories a card has. */
  it("card category links reach 24px inside the row's clip box, on one line", async () => {
    const p = await open();

    const m = await p.$$eval(".entry-cat .post-categories", (rows) =>
      rows.map((row) => {
        const r = row.getBoundingClientRect();
        const style = getComputedStyle(row);

        return {
          nowrap: style.whiteSpace === "nowrap",
          links: [...row.querySelectorAll("a")].map((a) => {
            const l = a.getBoundingClientRect();

            return {
              height: l.height,
              top: l.top,
              bottom: l.bottom,
              clipTop: r.top,
              clipBottom: r.bottom,
            };
          }),
        };
      }),
    );

    expect(m.length).toBeGreaterThan(0);

    for (const row of m) {
      expect(row.nowrap).toBe(true);

      for (const l of row.links) {
        expect(l.height).toBeGreaterThanOrEqual(24);
        expect(l.top).toBeGreaterThanOrEqual(l.clipTop);
        expect(l.bottom).toBeLessThanOrEqual(l.clipBottom);
      }
    }
  }, 30_000);
```

(`open()` already freezes transitions, so the padding is read at its final value.)

     never audit them. Open every group, audit both themes, and pin the

  it("has no WCAG 2.2 AA violations in the open phone footer, in both themes", async () => {
    if (!browser) throw new Error("no browser (beforeAll failed)");
    const p = await phonePage(browser);
    page = p;

    await p.evaluateOnNewDocument(() => {
      try {
        localStorage.clear();
      } catch {
        /* storage unavailable; nothing persisted to clear */
      }
    });

    await routeEcosystem(p, "fixture");
    await p.goto(`${ORIGIN}/`, { waitUntil: "networkidle0" });

    await p.addStyleTag({
      content:
        "*, *::before, *::after { transition: none !important; animation: none !important; }",
    });

    await p.evaluate(() => {
      for (const d of document.querySelectorAll<HTMLDetailsElement>(
        "details.footer-sitemap-collapsible",
      )) {
        d.open = true;
      }

      document
        .querySelector(".footer-sitemap")
        ?.scrollIntoView({ block: "center", behavior: "instant" });
    });

    for (const theme of ["light", "dark"] as const) {
      await p.evaluate(async (t) => {
        if (t === "dark") document.documentElement.dataset.theme = "dark";
        else delete document.documentElement.dataset.theme;

        await new Promise((resolve) => {
          requestAnimationFrame(resolve);
        });
      }, theme);

      const violations = await runAxe(p);

      expect(
        violations,
        report(`phone, footer open, ${theme}`, violations),
      ).toEqual([]);
    }

    const desk = await desktopPage(browser);

    try {
      await routeEcosystem(desk, "fixture");
      await desk.goto(`${ORIGIN}/`, { waitUntil: "networkidle0" });

      const margin = await desk.$eval(
        ".footer-sitemap-group li",
